## 《等等，为什么？》—— AI 阅读教学 Agent 系统

| 项目 | 内容 |
|---|---|
| 系统名称 | 等等，为什么（DengDeng） |

## 1. 系统定位

### 1.1 它不是一本书，是一个系统

| 错误的做法 | 本系统的做法 |
|---|---|
| 前端写死 10 页，翻页 = 前端切图 | **前端不知道下一页是什么，它问后端** |
| 故事、插画、判断逻辑都塞在页面里 | 内容在数据库，判断在 Agent 引擎，前端只负责演 |
| "AI" 是一个对话框 | Agent 是一条有状态、有目标的决策链路 |

**一句话**：内容是数据，产品是「观察 → 判断 → 决定给他什么」这个闭环。

### 1.2 系统要证明的事

同一章内容，不同孩子走出不同路径。路径由后端算出来，前端只负责呈现。

这是答辩时唯一需要证明的技术命题。**演示方式**：同一章读两遍（快读 / 慢读），看后端返回的片段序列是否不同。

## 2. 角色与边界

```
┌─────────────┐   REST + SSE   ┌──────────────┐
│   前端       │ ─────────────→ │   后端       │
│  只负责"演"  │ ←───────────── │  负责"算"    │
└─────────────┘                └──────┬───────┘
                                      │
                              ┌───────┴────────┐
                              │  Agent 引擎     │
                              │  负责"决定"     │
                              └───────┬────────┘
                                      │
                          ┌───────────┼───────────┐
                       内容库      学习状态库    LLM 服务
```

| 层 | 职责 | 明确不做 |
|---|---|---|
| 前端 | 渲染片段、上报行为、播放动效、展示对话 | 不判断下一页、不存业务状态 |
| 后端 | 会话管理、事件收集、状态计算、接口 | 不做动画、不写死内容 |
| Agent 引擎 | 评估学习状态、决定下一个动作 | 不直接输出长文（只产"意图"） |
| LLM | 只负责"把话说得像人" | 不做决策 |

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React 18 + Vite + TypeScript | 组件化、热更新、静态部署 |
| 前端状态 | Zustand | 轻，够用，不需要 Redux |
| 后端 | FastAPI + Uvicorn | 团队已熟悉；异步、SSE 原生支持 |
| ORM | SQLAlchemy 2.0 | 标准方案 |
| 校验 | Pydantic v2 | FastAPI 天然配套 |
| Agent | **LangGraph** | 状态图天然表达"观察→评估→决策"，可视化、可回放 |
| 数据库 | SQLite（开发）/ PostgreSQL（部署） | 开发零配置，生产可切换 |
| LLM | DeepSeek-chat 或 智谱 GLM-4-Flash | 中文好、便宜、OpenAI 兼容 |
| 部署 | Docker Compose | 一键起前后端 + DB |

**为什么用 LangGraph 而不是直接调 LLM**：决策需要可解释、可测试、可回放。LangGraph 的节点边界让"哪一步做错了"可定位，这也是答辩时能讲清楚的东西。

## 4. 数据库设计

### 4.1 内容侧

```sql
-- 章节
CREATE TABLE chapters (
  id           TEXT PRIMARY KEY,          -- 'ch02'
  title        TEXT NOT NULL,             -- '它背下了整本练习册'
  subtitle     TEXT,
  topic        TEXT,                      -- 'overfitting'
  order_no     INTEGER,
  created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 内容片段（核心表）
CREATE TABLE segments (
  id           TEXT PRIMARY KEY,          -- 'seg_p08'
  chapter_id   TEXT NOT NULL REFERENCES chapters(id),
  seq          INTEGER,                   -- 主线顺序，补充片段为 NULL
  kind         TEXT NOT NULL,             -- story | example | prompt | level | closing
  is_hook      INTEGER DEFAULT 0,         -- 0=主线，1=agent 可调度
  title        TEXT,
  body         JSON NOT NULL,             -- {"lines":[...], "note":"...", "bubbles":[...]}
  image_url    TEXT,
  goal_tag     TEXT,                      -- 对应教学目标 G1/G2/G3
  created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_seg_chapter ON segments(chapter_id, seq);
CREATE INDEX idx_seg_hook ON segments(chapter_id, is_hook);
```

**`is_hook` 是整个系统的关键字段。** 主线片段按 `seq` 排；补充片段没有 `seq`，只有 Agent 决定插入时才会出现在孩子眼前。

### 4.2 会话侧

```sql
CREATE TABLE sessions (
  id             TEXT PRIMARY KEY,        -- uuid
  chapter_id     TEXT NOT NULL,
  learner_name   TEXT,                    -- '小芽'，可空
  current_seg_id TEXT,
  started_at     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  finished_at    TIMESTAMP
);

-- 行为流水（只增不改）
CREATE TABLE events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  TEXT NOT NULL REFERENCES sessions(id),
  seg_id      TEXT,
  type        TEXT NOT NULL,              -- view|dwell|bubble_click|ask|answer|level_try|finish
  payload     JSON,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_ev_session ON events(session_id, id);

-- 学习状态（每个会话一行，随事件更新）
CREATE TABLE learn_states (
  session_id   TEXT PRIMARY KEY REFERENCES sessions(id),
  goals        JSON NOT NULL,             -- {"G1":{"state":"achieved"},"G2":{"state":"in_progress"}}
  misconceptions JSON NOT NULL,           -- {"M1":{"state":"cleared"},"M2":{"state":"triggered"}}
  profile      JSON NOT NULL,             -- {"dwell_avg_ms":4200,"fast_skips":2,"level_tries":5}
  updated_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 对话
CREATE TABLE messages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  TEXT NOT NULL REFERENCES sessions(id),
  role        TEXT NOT NULL,              -- user | book
  content     TEXT NOT NULL,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 问题本
CREATE TABLE question_book (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  TEXT NOT NULL REFERENCES sessions(id),
  question    TEXT NOT NULL,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 5. 接口设计

统一前缀 `/api`，JSON 交互，鉴权本期不做（本地演示）。

### 5.1 内容

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/chapters` | 章节列表 |
| GET | `/chapters/{id}` | 章节元信息 + 片段总数（**不返回全部正文**） |

### 5.2 会话

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/sessions` | 创建会话 `{chapter_id}` → `{session_id}` |
| GET | `/sessions/{id}` | 恢复会话：当前片段、学习状态 |
| POST | `/sessions/{id}/events` | 上报行为（见 5.3） |

### 5.3 事件上报（前端最常调）

`POST /sessions/{id}/events`

```json
{
  "type": "dwell",
  "seg_id": "seg_p08",
  "payload": { "ms": 2100 }
}
```

允许的 `type`：`view`、`dwell`、`bubble_click`、`ask`、`answer`、`level_try`、`finish`。

后端异步写入 `events`，并**增量更新 `learn_states`**。

### 5.4 核心接口：下一个片段

`GET /sessions/{id}/next?current=seg_p08`

**这是整个系统的枢纽。前端翻页时调它，后端跑一遍 Agent 图，返回"接下来该给孩子什么"。**

```json
{
  "action": "insert",            // continue | insert | repeat | back | ask_check | finish
  "reason": "p8 停留 2.1s，判定为快速翻过",
  "segment": {
    "id": "seg_extra_01",
    "kind": "example",
    "body": { "lines": ["你只见过红苹果。", "后来有人递给你一个青的。", "你会不会说：这不是苹果？"], "note": "它不是笨。它见过的，只有一种。" },
    "image_url": null
  },
  "state": { "goals": {"G1":"achieved","G2":"in_progress","G3":"untouched"} }
}
```

前端**只认 `action` 和 `segment`，从不自己决定**。

### 5.5 提问（流式）

`POST /sessions/{id}/ask` → `text/event-stream`

```
data: {"delta":"它"}
data: {"delta":"只见过"}
...
data: {"done":true,"citations":["seg_p07"]}
```

后端把提问 → 判定是否在本章范围 → 范围内走 LLM 生成，范围外返回"记进小本子"并写入 `question_book`。

### 5.6 关卡作答：通用关卡接口

`POST /sessions/{id}/level`

```json
{ "seg_id": "seg4_p08", "item_id": "tg1", "action": { "labels": { "ph5": "鳄鱼" } } }
```

**为什么不是 `/answer` + `a`/`b`**

最初的 `/answer` 把第 2 章的机器写死在接口签名里（`a` 和 `b` 两个整数）。第三、四章的关卡不是算术，这个接口就用不了。

现在接口只做分派，**机器怎么反应由内容里的 `body.level.kind` 决定**：

| kind | 机器行为 | 用在 |
|---|---|---|
| `arithmetic` | 不管什么题，都算 `a + a` | 第 2 章 |
| `confidence` | 答什么都一样有把握（100%） | 第 3 章 |
| `label` | 它的认识清单＝别人贴的标签；没标的就硬挑一个最像的 | 第 4 章 |
| `stripes` | 加够几道线就改口，而且改口时一样确定 | 第 5 章 |
| `prompt` | 顺着孩子问法里出现的那个词走，不纠正 | 第 6 章 |
| `chain` | 给什么开头接什么，不判断真假 | 第 7 章 |
| `feed` | 数孩子点过什么，推出现最多的那种 | 第 8 章 |
| `memory` | 只留最近 N 条，再往前直接丢，不留痕 | 第 9 章 |
| `sort` | 只记录孩子怎么分类，**不做判定** | 第 10 章 |

实现在 `app/services/levels.py`，是一组纯函数，可单测（`tests/test_levels.py`，10 个用例，含"故意用虚构章节数据"的验证）。

**新增一种玩法的代价**：后端加一个 handler，前端加一行 `kind → 组件` 映射。`Page.tsx` 和接口都不用动。

这是能往下加七章的前提 —— 否则每章都要改前端代码。

`POST /sessions/{id}/answer` 保留兼容，新代码一律走 `/level`。

### 5.7 学习状态（调试/答辩用）

`GET /sessions/{id}/state` → 完整 `learn_states` + 最近 20 条事件。前端用它在角上画那个"它在想什么"的面板。

## 6. Agent 引擎设计

### 6.1 状态图

```python
# app/agent/graph.py
from langgraph.graph import StateGraph, END

class AgentState(TypedDict):
    session_id: str
    chapter_id: str
    current_seg: str | None
    recent_events: list[dict]
    goals: dict
    misconceptions: dict
    profile: dict
    action: str | None
    target_seg: str | None
    reason: str

g = StateGraph(AgentState)
g.add_node("observe", observe)   # 拉取最近事件，算停留、跳过、作答情况
g.add_node("assess",  assess)    # 更新教学目标与误区
g.add_node("decide",  decide)    # 规则决策 → action
g.add_node("select",  select)    # 按 action 选出片段
g.set_entry_point("observe")
g.add_edge("observe", "assess")
g.add_edge("assess", "decide")
g.add_edge("decide", "select")
g.add_edge("select", END)
```

**四步，全部是确定性代码。LLM 不在这条链上。**

### 6.2 决策规则（可解释、可单测）

```python
# app/agent/rules.py
def decide(st: AgentState) -> AgentState:
    dwell = last_dwell_ms(st["recent_events"])
    fwd = consecutive_fast_skips(st["recent_events"])

    if st["current_seg"] == "seg_p08" and dwell < 3500 and not inserted(st, "seg_extra_01"):
        return {**st, "action": "insert", "target_seg": "seg_extra_01",
                "reason": f"p8 停留 {dwell}ms，判定为快速翻过"}

    if st["misconceptions"]["M2"]["state"] == "triggered" and not st["misconceptions"]["M2"]["state"] == "cleared":
        return {**st, "action": "ask_check", "target_seg": "seg_probe_m2",
                "reason": "检测到误区 M2：以为机器是故意的"}

    if fwd >= 3:
        return {**st, "action": "back", "target_seg": "seg_p07",
                "reason": "连续 3 页快速翻过，回退到练习册"}

    return {**st, "action": "continue", "target_seg": next_main_seg(st), "reason": "正常推进"}
```

规则表可以随着教学策略增加，**每加一条就是加一行 if**，不需要重训任何东西。

### 6.3 LLM 只做两件事

| 场景 | 输入 | 输出限制 |
|---|---|---|
| 生成书的台词 | 片段意图 + 当前页 + 角色语气 | ≤ 2 句，≤ 20 字/句 |
| 回答孩子的提问 | 问题 + 本章上下文 + 术语降维表 | ≤ 60 字，超纲即记本子 |

Prompt 里强制约束：不出现"数据、训练、模型、算法"等词；不确定就说不确定。

## 7. 一次翻页的完整时序

```
孩子点"下一页"
      │
      ├─ 前端 POST /sessions/{id}/events   {type:"dwell", ms:2100}
      │
      ├─ 前端 GET  /sessions/{id}/next?current=seg_p08
      │        │
      │        ├─ observe  取最近事件
      │        ├─ assess   dwell<3.5s → profile.fast_skips += 1
      │        ├─ decide   → action="insert", target="seg_extra_01"
      │        └─ select   从 segments 表取补充片段
      │        │
      │        └─→ {action:"insert", segment:{...}, reason:"..."}
      │
      ├─ 前端识别 action=insert → 在当前位置插入一个页面并渲染
      │
      └─ 若 action=ask_check → 前端额外调 POST /ask 拿流式台词
```

**关键点**：前端从不知道"下一页是第几页"，它只知道"后端让我给他这一段"。这才叫 agent 驱动。

## 9. 非功能设计

| 项 | 目标 | 手段 |
|---|---|---|
| `/next` 延迟 | < 200ms | 决策全为本地规则，不调 LLM |
| `/ask` 首字延迟 | < 1.5s | SSE 流式；超出则先回"让我想一想" |
| 单章内容体积 | < 300KB | 图片 WebP + 懒加载 |
| LLM 成本 | 单次会话 ≤ 10 次调用 | 只有提问和台词走模型 |
| 降级 | LLM 不可用时全章可读 | 预置答案库 + 模板台词 |
| 并发 | 演示规模（< 20） | Uvicorn 单进程即可，不做集群 |

## 11. 答辩要演示的三个场景

1. **快读**：一路连点，后端返回 `insert`，中间多出一页生活例子 → 证明内容是被调度的
2. **慢读**：在 p8 停留 8 秒，后端返回 `continue` → 证明它在观察，不打扰
3. **提问**：问一个超纲问题，它说"这个我还答不上来"并记进本子 → 证明它知道自己不知道

每一场景都打开 `AgentPanel`，让评委看到 `reason` 字段。**reason 是给人看的设计**，它让"智能"变得可审。

## 13. 开放问题

1. 数据库用 SQLite 还是直接上 Postgres（影响 Docker 复杂度）
2. LLM 用 DeepSeek 还是智谱（影响 key 申请与成本）
3. 是否需要"教师端"看全班学习状态（加分项，但会拖一周）
4. 补充片段做 3 个还是 5 个
